# 个性化：方案与取舍

> 设计侧文档。实现口径（token、契约、同步协议）见 [../engineering/theme-system.md](../engineering/theme-system.md)，
> 行为代码在 `web/src/styles/theme/personalization.ts`、`accents.ts` 与 `stores/app/ui.ts`。

## 1. 要解决的问题

"Citebase 支持四套外观"这句话在**产品上**是真的，在**账号上**曾经是假的：外观、材质、透明变体只住 localStorage，换设备、清缓存、换浏览器就全丢。同时，系统层面的无障碍设置（减弱动效、提高对比度、减弱透明度）只能靠 `@media` 被"顺带遵守"，应用没有显式表达出口。

个性化这一层的目标因此有两半：

1. **把外观与行为变成账号属性**，跨设备一致；
2. **给系统设置一个应用内出口**——不是替代系统开关，而是让用户在"这个应用里"能表达得更细。

## 2. 四个批次做了什么

| 批次 | 内容 | 落点 |
|---|---|---|
| 批前 | 外观（4 套）+ 材质（实心/玻璃）+ 玻璃 Clear 变体 | `themes.ts` |
| 批1–2 | 动效强度、对比度、透明度三档（默认 `auto`） | `personalization.ts` + `ui.ts` |
| 批3 | 强调色 8 档 + `auto` | `accents.ts` |
| 批4 | 版面人格 `plain` / `signature`（公开版面入场编排） | `personalization.ts` + CSS 选择器族 |

合起来，账号偏好载荷是八格：`theme` / `material` / `glass_clear` / `motion` / `contrast` / `transparency` / `accent` / `persona`。

## 3. 五条设计原则

**① 默认值必须等于"什么都没做"。**
三条行为档默认 `auto`，强调色默认 `auto`，人格默认 `plain`。新访客第一眼看到的仍是原来的样子——个性化是"用户明确要了才给"，不是"上线就替所有人改观感"。

**② 系统信号是三个独立信号，不是一档。**
`prefers-reduced-motion`、`prefers-contrast: more`、`prefers-reduced-transparency` 可以单独开。合并成一个"无障碍开关"会漏掉一批用户：只开"提高对比度"的人，不该被顺手把动效也关掉。

**③ 显式选择可以盖过系统信号，但界面必须显示"现在生效的是什么"。**
`auto` 是"没表过态"，此时尊重系统；用户显式选 `full` 是一次应用内表态，比全局开关更贴近他此刻的意图（Apple 的原话是 "Make motion optional"，可选性本来就是双向的）。代价是跨设备时可能与本机系统开关相反——所以界面不能只显示"你选了 full"，必须显示"当前生效 full / soft / reduced 哪一档"。

**④ 强调色给色板，不给取色器。**
`--apple-on-blue`（实心强调色上的前景）是注入时按色值算出来的，浏览器不能按亮度分支。允许任意 hex，就等于放出一条没人验过的路径：浅色板（如 `#ffe100`）上白字只有 1.4:1。固定 8 档在 OKLCH 上等亮度等彩度、只变色相，整板一次过 `check:contrast`。Apple 也是同一取舍：一排色卡 + graphite + 自动，而不是取色器。

**⑤ 入场编排只给"公开版面"。**
`persona=signature` 的编排只准出现在登录 / 授权登录 / 安装向导 / 分享页 / 整页错误（门禁 G34）。理由不是审美，是 HIG："不要在高频交互上加动效"。产品内页是高频工作面，编排在那里只会变成每次切页的等待。

## 4. 各档的语义边界

| 档 | 它改变什么 | 它不改变什么 |
|---|---|---|
| `motion` | 时长倍数（1 / 0.6 / 0.0001）与 `reduced` 的"不位移只淡入淡出"通配 | 不改变布局与信息层级；动画关闭不等于功能消失 |
| `contrast` | 描边是否画实、表面是否近实心 | 不改主题色相；不是"高对比主题" |
| `transparency` | 玻璃是否退回该外观的不透明表面 | 不改变材质轴的选择值本身（回 `full` 时仍是玻璃） |
| `accent` | 强调色与它派生的浅染/前景族 | 不改语义色（成功/警告/错误）与图表专属色板 |
| `persona` | 公开版面的入场编排 | 不改产品内页的任何动效 |

## 5. 明确不做的事

- **不做通知/邮件文案的运行时翻译**。通知标题正文是事件发生时**落库的冻结文本**，读时翻译不可能；要本地化得存"键 + 参数"，是产品决策，当前没做。
- **不做 SSE 帧内工具错误的翻译**。帧里是工具原文，直出。
- **不做"任意强调色"**（理由见原则④）。
- **不做"整站统一动效开关"**：动效的可达性由 `reduced` 档 + 系统信号覆盖，但“关掉一切动效”会把"状态变化"也关掉，那不是可达性，是功能缺失。

## 6. 用户在哪里碰到它

- 设置页「外观」：外观、材质（含 Clear 变体）、强调色、三条行为档、版面人格；
- 顶栏主题菜单（`ApThemeMenu`）：快速切外观/材质，标签显示**当前生效档**；
- 首访与升级：老数据行按 theme-system §6 的例外规则读——外观/材质认不得判"没配过"，新格缺失用本机值补，不会把老账号打成"坏数据"。

## 7. 验收

- 静态：`npm run check:style`（G32/G33/G34、T 系列）+ `npm run check:contrast`（全色板）；
- 运行时：`npm run check:theme-rounds -- --themes=all`（八档都真的切过去、材质真的改变渲染、浮层 alpha 在区间内、运行时对比度过线）；
- 账号：`go test ./tools/repocheck/ -run Preference -count=1`（前后端清单逐条一致，含每档默认值）。
